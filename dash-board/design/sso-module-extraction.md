# SSO 설계

KTIS SSO 연동을 유지한다. `security-portal-admin`의 OTT 교환 흐름을 Python / FastAPI로 옮기며, 원본 서비스의 직원·메뉴·승인 등 업무 기능은 가져오지 않는다.

## 로그인 흐름

1. 사용자를 SSO 허브의 `/slogin`으로 보낸다.
2. 허브가 `/sso/callback`에 일회성 `ssoToken`을 전달한다.
3. FastAPI가 `/api/ott/exchange`에 토큰을 보내 사번을 받는다.
4. 사번으로 사용자를 조회하고, 최초 로그인 시 등록하며 기존 사용자의 로그인 시각을 갱신한다.
5. 서버 세션을 만들고 브라우저에 HttpOnly 쿠키를 발급한다.

현재 로그인 후 기본 이동 위치는 `/api/auth/me`다. React 대시보드 구현 시 기본 이동을 `/dashboards`로 변경한다. 요청했던 화면으로 돌아갈 때는 허용된 같은 출처의 상대 경로만 받는다.

## 사용자와 권한

사용자·역할·세션은 시스템 DB에 저장한다. 사번을 사용자 식별에 사용하며 기본 역할은 `ROLE_USER`다. 지정된 초기 관리자 사번에는 `ROLE_SYSTEM`을 부여할 수 있다.

현재 교환 응답에서 사용하는 정보는 사번이다. 이름·조직 정보 제공 여부는 확인이 필요하며, 이름이 없으면 사번을 표시명으로 사용한다. 관리자 역할이나 SSO 인증만으로 업무 데이터 공개 정책을 대신하지 않는다.

## 세션

브라우저에는 랜덤 세션 토큰을 전달하고 DB에는 해시만 저장한다. SSO 토큰 원문은 저장하지 않는다. 서버에서 만료와 사용자 활성 상태를 확인하고 로그아웃 시 세션을 삭제한다. 미인증 API 요청은 401로 처리한다.

업무 API는 현재 사용자 조회와 인증 필수 dependency를 사용한다. 개발 자동 로그인은 로컬 검증용이며 실제 SSO 연동 검증과 구분한다.

대시보드 API는 사용자 활성 상태와 공개 상태를 확인한다. 관리자 API는 추가로 `ROLE_SYSTEM`을 검사한다. React는 `/api/auth/me` 결과로 메뉴를 표시하고 세션 쿠키를 사용하며, 인증 토큰을 localStorage에 저장하지 않는다.

신규 사용자는 기본 이용자로 등록한다. 관리자는 초기 설정으로 지정하며, 대시보드 작성자가 됐다는 이유로 관리자 권한을 부여하지 않는다. 역할을 변경하면 다음 요청부터 DB의 현재 역할을 적용한다.

## 실제 연동 시 확인

- SSO 허브 주소와 서버의 OTT 교환 주소
- 허브에 등록할 callback URL
- 교환 응답의 사번 필드와 추가 사용자 정보
- 세션 쿠키와 로그아웃 동작

설정과 실행은 [백엔드 README](../backend/README.md), API 경로는 [API 범위](api-contract.md)를 따른다. 현재 모듈 구현과 별도로 실제 허브 연동은 검증이 필요하다.
