# 보안·운영 기본 기준

현재 PoC와 이후 업무 기능에 필요한 기준이다. 아래 항목은 배포 시 확인할 요구사항이며, 모두 구현·검증됐다는 의미는 아니다.

## 인증과 접근

- KTIS SSO를 유지하고, 사번과 시스템 내 역할로 사용자를 식별한다.
- 세션은 서버에서 관리한다. 만료되거나 비활성화된 사용자는 보호 API에 접근할 수 없어야 한다.
- 화면 표시 여부와 관계없이 서버에서 접근 권한을 검사한다.
- SSO 로그인 성공과 업무 데이터 열람 권한을 구분한다.
- 상태 변경 요청에는 교차 사이트 요청 방지 처리를 적용한다.
- 대시보드 관리자 API 전체에 관리자 역할 검사를 적용한다. 조회용 API는 항상 서버의 공개본만 사용한다.
- 공개 대상은 초기에는 활성 SSO 사용자 전체다. 해당 범위에 허용되지 않은 원천 데이터는 등록하지 않는다.
- 개발 자동 로그인은 로컬 확인에만 사용하고 공유 환경에서는 끈다.

## 인증정보와 외부 호출

SSO 토큰, 세션 쿠키, API 키와 원본 업무 데이터 전문을 로그나 오류 응답에 남기지 않는다. 콜백 URL의 토큰이 접근 로그에 기록되는지도 확인한다.

비밀정보는 환경변수 등 서버 설정으로 주입한다. 브라우저에 외부 API 인증정보를 전달하지 않는다. 외부 호출은 정해진 주소를 사용하고 시간 제한과 TLS 인증서 검증을 적용한다.

신규 JSON API의 POST·PUT·DELETE는 SameSite 쿠키, 정확한 Origin 검사, application/json과 사용자 정의 요청 헤더를 함께 요구한다. 다른 출처 CORS는 허용하지 않는다. 이 정책은 읽기 전용 query/preview POST에도 적용한다. SSO GET callback은 이 Origin 검사 대상에서 제외하고 토큰 교환으로 인증한다. 기존 logout은 헤더 검사에 Origin 검사를 보강한다.

제목·설명은 일반 텍스트로 렌더링한다. 서버는 위젯·필드·지표·정렬을 허용 목록으로 검증한다. 편집 요청으로 URL·SQL·실행 코드를 전달할 수 없어야 한다.

공개 설정과 업무 데이터 응답에는 private, no-store 캐시 정책을 적용한다. 서버는 데이터 조회가 끝난 뒤에도 사용자·공개 상태를 재검사한다. 로그에는 초안 저장·공개·공개 중지·삭제의 사용자·대상·결과를 남기고 별도 감사 시스템은 초기 범위에서 제외한다.

## 공유 배포 전 확인

- 접근 대상과 업무 데이터 공개 범위를 정한다.
- HTTPS와 Secure 쿠키를 적용하고 프록시 사용 시 신뢰할 헤더 범위를 정한다.
- 세션 만료·로그아웃·비활성 사용자 차단을 확인한다.
- 로그인·외부 조회 실패를 추적하되 민감정보를 기록하지 않는다.
- DB 종류와 보존할 데이터가 정해지면 백업·복구 방법을 확인한다.

캐시 운영, 로그 보존 기간, 복구 목표와 인프라 구성 수치는 실제 운영 조건에 맞춰 정한다.
