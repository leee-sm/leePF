# 데이터 연동 기준

재고는 첫 PoC 데이터 소스다. 샘플 JSON에 대해 확정한 계산과 아직 확인되지 않은 필드 의미를 구분한다. 화면 범위는 [서비스 디자인](product-design-blueprint.md)을 따른다.

## 연결 범위

첫 PoC는 `data/inventory_20260908.json`, `inventory_20260909.json`, `inventory_20260910.json`을 날짜별 고정 스냅샷으로 읽는다. 관리자의 파일 업로드·교체 기능과 실제 업무 API 연결은 이번 범위에서 제외한다. MCP는 보류한다.

관리자는 서버에 등록된 데이터 소스를 선택한다. 소스는 활성 SSO 사용자 전체에게 공개 가능한 자료만 등록하는 초기 정책을 따른다. 소스가 비활성화되거나 공개 허용이 철회되면 기존 대시보드도 데이터 조회를 거부한다.

원천 담당자는 데이터 의미와 제공 방식, 업무 담당자는 지표의 계산 기준을 확인한다. FastAPI는 조회·변환·필터·계산과 접근 검사를 담당한다. 원천에 여러 테이블이 있어도 필요한 조합 결과를 API로 받는 것을 우선한다.

## 실제 업무 API 연결 시 필요한 정보

| 항목 | 확인할 내용 |
|---|---|
| 데이터 단위 | 한 행의 의미, 별도 수량 필드와 식별자 유무 |
| 날짜 | 기준일 의미, 전체 스냅샷 여부, 조회 가능한 날짜 |
| 주요 필드 | 표시명, 타입, 단위, 빈 값과 0의 의미 |
| 조회 조건 | 지원 필터, 결과 크기와 페이지 처리 필요 여부 |
| 데이터 접근 | 연결 주소, 인증 방식, 사용자에게 허용되는 범위 |
| 장애 처리 | 정상 0건, 조회 불가 날짜, 인증 실패, 일시 장애 구분 |

별도 데이터 탐색 API나 범용 조회 규격을 원천에 요구하지 않는다. 선택한 업무를 조회하는 데 필요한 요청·응답만 합의한다.

## 재고 샘플에서 확인할 필드

샘플의 행 위치는 `response.inventories`다. 아래는 표시명 후보이며, 원천 담당자 확인 없이 업무 정의로 확정하지 않는다.

| 원천 필드 | 의미 후보 |
|---|---|
| `upldDt` | 기준일 또는 업로드일 |
| `agnId`, `cpLetr` | 대리점 식별자, 거래처명 |
| `repDvcId`, `mnfct` | 모델 코드, 제조사 |
| `dvcClNm`, `dvcColrNm` | 단말 분류, 색상 |
| `outUnitPric` | 출고 단가 후보. 샘플의 0은 가격 미등록 |
| `outPassovrDay` | 출고 후 경과일 후보. 0의 업무 의미는 미확정 |

첫 PoC의 재고 수량은 `response.inventories`의 행 수다. 내용이 완전히 같은 행도 각각 재고 한 대로 세며 중복 제거하지 않는다. 샘플의 가격 0은 미등록으로 처리하며, 총 단말기 금액은 종료일의 같은 필터 적용 행에서 양의 정수형 `outUnitPric`를 원 단위로 합산한다. 등록 가격 합계와 가격 등록·미등록 대수를 함께 표시한다. 중복 행은 별도 단말기로 합산하며, 누락·0·음수·잘못된 형식의 가격은 합계에서 제외한다. 재고는 있지만 등록 가격이 전혀 없으면 금액 확인 불가, 정상 재고 0건이면 0원으로 표시한다. 대시보드는 종료일 스냅샷의 `outPassovrDay` 값을 0~29일, 30~59일, 60~89일, 90일 이상으로 중복 없이 집계하고 같은 제조사·모델 조건을 적용한다. 값 0은 0~29일에 포함하며 정수형이 아닌 값과 음수는 판정 불가로 별도 표시한다. 보유처별 재고는 같은 필터 적용 행의 거래처명 `cpLetr` 기준으로 집계하고 빈 이름도 미등록으로 포함한다. 집계 표의 수량 막대는 페이지 최대값이 아닌 조회 재고 전체 대비 비율을 사용한다. 이 필드의 업무 정의와 0의 의미가 확정되지 않았으므로, 이 집계는 원본 경과일 후보 필드 기준이며 물리적인 재고 보유 기간으로 해석하기 전에 원천 담당자 확인이 필요하다.

샘플 최상위 `timestamp`는 데이터 기준일이나 원천 갱신 시각으로 확정하지 않는다. 기준일은 파일명과 행의 `upldDt`로 검증하고, 원천 갱신 시각은 확인 불가로 표시한다.

2026-09-08 파일은 `status=200`, `inventories=[]`이며 정상 재고 0건으로 표시한다. 2026-09-09는 10,236건, 2026-09-10은 10,759건이다. 조회 가능일은 세 날짜 모두이며 기본값은 최신 날짜인 2026-09-10이다. 다른 날짜는 조회 가능일로 제공하지 않는다.

## 계산·표시 원칙

- 동일 내용의 행도 별도 재고로 세며 중복 제거하지 않는다.
- 전체 스냅샷으로 확인된 데이터는 날짜별로 합산하지 않는다.
- 증감 기능을 선택하면 비교일을 표시하고 양쪽에 같은 필터를 적용한다.
- 가격 누락과 잘못된 값을 임의의 정상 가격으로 바꾸지 않는다.
- 데이터 없음과 조회 실패를 구분하며, 실패를 수량 0으로 표시하지 않는다.
- 기준일과 조회 시각을 구분하고, 원천 갱신 시각은 제공될 때 표시한다.

첫 지표 `inventory_count`는 종료일의 필터 적용 후 행 수다. 카드, 차트, 표는 같은 종료일·제조사·모델 필터가 적용된 행을 사용한다. 제조사·모델의 빈 값은 누락 항목으로 표시하고 전체 수량에서는 제외하지 않는다. 실제 API 연결 성공 여부는 샘플 검증과 별도로 기록한다.

## 편집기에 제공할 메타데이터

| 항목 | 서버가 관리하는 내용 |
|---|---|
| 소스 | ID, 표시명, 설명, 활성 여부, 허용 공개 대상 |
| 필드 | ID, 표시명, 타입, 단위, 분류·날짜·필터 사용 가능 여부 |
| 지표 | ID, 표시명, 단위, 계산 규칙, 함께 사용할 수 있는 분류 |
| 필터 | ID, 유형, 필수 여부, 후보값 조회, 허용 기본값 |
| 조회 방식 | 첫 PoC는 실제 조회 가능 날짜만 포함하는 시작일·종료일 범위와 날짜별 스냅샷 추이 |
| 호출 제한 | 시간 제한, 최대 행 수·응답 크기, 페이지 처리 방식 |

필드·지표 목록은 코드나 서버 설정으로 등록한다. 편집기는 목록을 선택지로 표시하며 직접 수식이나 기술 필드 경로를 작성하게 하지 않는다. 스키마 탐색 엔진은 만들지 않는다.

## 조회와 계산

1. 공개본 또는 검증된 미리보기 설정과 필터를 읽는다.
2. 사용자·소스 권한, 필수 조건과 실제 조회 가능한 종료일을 서버에서 검사한다. 화면은 시작일도 실제 날짜 목록에서 고르고 종료일보다 늦지 않은지 검사한다.
3. 원천을 조회하고 응답의 완전성·타입을 확인한다.
4. 공통 필터를 적용한 같은 결과로 모든 위젯을 계산한다.
5. 표는 집계 후 정렬·페이지 처리하고 차트는 정렬 후 상위 항목을 선택한다.
6. 데이터 기준일·조회 시각과 함께 반환한다.

원천의 페이지 응답은 허용 한도 안에서 필요한 페이지를 모두 조회한 뒤 계산한다. 일부 페이지만으로 전체 수량을 계산하지 않는다. 한도 초과나 페이지 누락은 조회 실패로 처리하며, 데이터가 커지면 원천 집계 API를 협의한다.

표 정렬은 사용자가 선택한 열 뒤에 분류 키를 보조 정렬로 적용해 같은 원천 결과에서 안정적으로 페이지를 나눈다. 요청 사이 원천 데이터가 바뀌면 결과도 바뀔 수 있으며, 첫 버전에서는 요청 간 스냅샷 고정을 보장하지 않는다.

첫 버전은 필수 데이터나 계산 오류가 있으면 조회 전체를 실패 처리한다. 잘못된 결과 일부를 정상 화면과 섞지 않는다. 업무 규칙상 허용된 누락만 경고로 반환한다.

## 지표 등록 예

`inventory_count`는 종료일 스냅샷의 필터 적용 후 행 수를 센다. 제조사별·모델별 막대 차트와 집계 표도 같은 종료일 스냅샷을 분류별로 묶는다. 추이는 선택 범위 안에 실제로 제공된 스냅샷마다 같은 분류 필터를 적용한다. 날짜별 수량을 더해 기간 재고로 취급하지 않는다. 경과일 요약도 종료일의 같은 필터 적용 행에서 `outPassovrDay`를 0~29일, 30~59일, 60~89일, 90일 이상으로 나눈다. 값 0을 첫 구간에 포함하되 업무 의미가 미확정임을 별도 안내한다. 재고 기간 조회 조건은 전체 또는 0~29일, 30~59일, 60~89일, 90일 이상 중 하나다. 구간 막대를 선택하면 즉시 조회하며 수량·보유처·금액·추이·상세 표와 CSV에 같은 구간 및 제조사·모델 조건을 적용한다. 경과일 판정 불가 행은 전체 조회에 포함하되 특정 구간 조회에서는 제외한다. 총 단말기 금액은 원본 출고 단가의 등록 가격 합계이며 미등록 가격이 있는 경우 전체 재고의 완전한 평가액으로 취급하지 않는다.

서로 다른 날짜의 재고는 합산하지 않는다. 기간 변화는 시작일과 종료일의 필터 적용 행 수 차이로 계산하고, 양쪽에 같은 제조사·모델 조건을 적용한다. 실제 조회 가능한 날짜만 시작일·종료일로 선택할 수 있고 잘못된 범위는 조회하지 않는다. 조회 조건을 편집하는 동안 마지막 성공 결과를 유지하며 조회를 눌렀을 때 새 조건을 적용한다. 정상 0건 스냅샷은 수량 0으로 표시한다.

정상 0건의 건수·합계는 0, 분모가 0인 비율은 계산 불가다. null 값을 0원이나 정상 수치로 임의 치환하지 않는다. 선택지 조회가 길어지면 검색·cursor로 나누고, 사용자 선택값의 유효성은 서버에서 다시 검사한다.
